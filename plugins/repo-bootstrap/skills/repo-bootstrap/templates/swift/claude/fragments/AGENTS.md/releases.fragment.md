**Releases.** Tagging `v*` triggers `.github/workflows/release.yml`, which forwards to the shared immutable `release-swift.yml@41f8de6765b3b833ef333b0b98f5683f0e46685b` reusable workflow: a universal (arm64 + x86_64) `swift build`, a GitHub release, and a Homebrew binary cask pushed to `{{GITHUB_USER}}/homebrew-tap`. The executable product must keep the repo's name, and its `--version` output must exactly equal the tag without the leading `v`; bump `ReleaseVersion.current` in `Sources/<name>/Version.swift` in the release commit. The release refuses to run unless the tagged commit is on `main` — tag a merged commit (e.g. `git tag vX.Y.Z origin/main`), not a feature branch. One-time setup requires `HOMEBREW_TAP_TOKEN` plus all five `MACOS_*` repository secrets. The binary is Developer-ID-signed and notarized; missing credentials or version drift fail the release before publication (see `reference/swift-ci-and-release.md`).
