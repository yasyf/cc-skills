## asks

_Which owner asks are still open, and what finishes each one?_

**Open asks.** The ledger's `ask/*` rows that are not dropped, answered or delivered (every linked PR landed), with their accept
criteria; `keys` narrows to named rows. Open cci asks addressed to any `cci_to` reader join them.

Reads: `ccn ledger row list`, `cci digest`.

## boards

_Which cc-present boards are open and still asking the owner something?_

**cc-present boards.** cc-present boards updated since the drive started; an open, unsubmitted board that asks something reads warn.

Reads: `cc-present sessions`, `cc-present outcomes`.

## cci-lanes

_Which lanes are working, idle, stood down, or still holding a worktree?_

**Lanes.** Each lane's latest cci record, grouped active, idle past `idle_hours`, stood down, and stood down while still holding
a worktree of the drive's checkout; Orca workers needing attention join when the drive has an Orca run.

Reads: `cci lanes`, `git worktree list`, `orca orchestration worker-list`.

## ci-builds

_Which recent CI builds passed, failed, or are still running?_

**CI builds.** Recent builds from Buildkite (`bk api`, by `pipeline`) or GitHub Actions (`gh run list`, by `repo`), on `branch` when set.

Reads: `bk api`, `gh run list`.

## dashboard-health

_Is every card on this page fresh and running?_

**Dashboard health.** Every card on this dashboard with its status, the age of its last good payload, its last run time, and its error.

Reads: `the dashboard scheduler`.

## datadog-monitors

_Are this work's Datadog monitors OK, alerting, or not created yet?_

**Datadog monitors.** Monitors matching a Datadog monitor search `query` through pup, as gates: OK passes, Alert fails, Warn blocks, No Data
has not run. Each name in `expect` that matches no monitor shows as not created.

Reads: `pup monitors search`.

## design-gates

_Which design register entries are still open, and what blocks each one?_

**Design gates.** Register entries `ids` from `<doc>/registers.json` at `ref` in a design-doc checkout, as gates: closed, resolved or
validated pass; invalidated fails; anything else is open, blocked on the decisions it blocks. `owners` and `closes`
name who owns each gate and the PR that closes it.

Reads: `git show <ref>:<doc>/registers.json`.

## gates

_Which gates still stand between this work and done?_

**Gates.** Named gates, each read from one source: `pr:N` (landed passes; blocked carries the queue's reason), `file:<glob>`
(a match passes, none has not run), `ledger:<key>` (landed or answered passes), `monitor:<query>` (all OK passes,
any Alert fails, none is not created), or `status:<status>` held by hand until the gate's owner updates it.

Reads: `ccx vcs pr status`, `files`, `ccn ledger row list`, `pup monitors search`.

## gh-quota

_How much GitHub API quota is left before cards stop refreshing?_

**GitHub API quota.** REST core and GraphQL remaining quota from `gh api rate_limit`, which spends none; under `floor` reads bad.

Reads: `gh api rate_limit`.

## held-prs

_Which PRs are held, why, and what lifts each hold?_

**Held PRs.** Open ledger PRs carrying a hold (reason, since, until), joined with the lines of a holds file that name the PR by
`#N` or its lane by `lane:<name>`; a line containing LIFT, LIFTED or LIFTS counts as lifted and is skipped.

Reads: `ccn ledger row list`, `holds file`.

## incident-feed

_Which incidents opened or moved in the last few days?_

**Incidents.** Incident, evidence, mechanism, fix-live, recovered, not-ours, duplicate and done records from the last `hours`.

Reads: `cci records`.

## kv-file

_What are the latest numbers in this file?_

**Numbers from a file.** One tile per top-level key of a JSON object file, or per `key: value` line; `keys` picks and orders them.

Reads: `JSON or key: value file`.

## landing-preview

_If the owner approves each stack's bottom now, what lands?_

**What an approval lands.** Reads the `graph` card's stacks and the `queue` card's verdicts: per stack, which PRs approving its bottom lands now,
the first PR the prefix stops at and why, and how many PRs wait behind it.

Reads: `the stack-graph card`, `the pr-review-queue card`.

## latency-percentiles

_How fast is it at p50, p95 and p99, against its budget?_

**Latency percentiles.** p50, p95, p99 and max per group, with a p95 history. Three sources: `files` rows (json, jsonl, csv, tsv) with a
`value` sample, a `group` field and a `failure` flag counted apart (`!success` counts a false `success`); `deltas_from` plus `deltas_to`, the time from one
timeline entry to each later stage across every file matching `files`; or a Datadog `query` through pup. Every named
`groups` entry shows as not run until it has samples, and `budgets` overrides `budget_ms` per group. Every budget is a
rule on the history, which plots one point per file, so a timeline per run reads as one point per run.

Reads: `result files`, `timeline files`, `pup metrics query`.

## log-matches

_How often do the watched patterns show up in the log, and when last?_

**Log matches.** For each named regex in `patterns`, how many of the last `lines` lines of a log file match and when the newest match
was logged, read from a leading ISO time. The line text never reaches the board.

Reads: `log file`.

## matrix-file

_Which cells pass, fail, or have not run yet?_

**Matrix from a file.** The newest file matching `file` (JSON, JSONL, CSV, TSV, or a markdown table picked by `table`) as a grid: each result
row lands in the cell its `row` and `col` fields name, showing its `value`, opening its `link` field, and hovering its
`detail` fields; a later row for the same cell wins. `rows` and `cols` fix the order and show cells with no result as
`missing`. A value tones by `tones`, else pass is ok, fail bad, pending or rerun-pending warn, untested muted.

Reads: `result file`.

## notes

_What did cc-notes record lately for this work?_

**cc-notes records.** cc-notes plans, docs, logs, investigations and answers in the drive checkout, newest first; `label` narrows docs.

Reads: `ccn`.

## open-records

_Which cci blockers, defects and holds are still open, and which went stale?_

**Open cci records.** The cci digest's open blockers, defects and holds since the drive started, minus cites a `resolved:` done record
closed. A record is stale when it names a PR whose ledger head no longer matches the SHA it cites, or when a later
READY or HEAD record exists for that PR. Action `close` posts `done --topic resolved:<cite>`.

Reads: `cci digest`, `cci records`, `ccn ledger row list`.

Actions: `close`.

## orca

_Which Orca tasks are running, and which workers need attention?_

**Orca tasks.** The drive's Orca run: each task with its status, and the workers whose projection asks for attention.

Reads: `orca orchestration task-list`, `orca orchestration worker-list`.

## pr-review-queue

_Which PRs wait on review, and what exactly gates each one?_

**PRs waiting for review.** Open PRs from `prs`, else the ledger's open rows: size, CI without the ignored checks, the review bot's check, the
ledger's rules-review verdict at the current head, unresolved threads, the queue verdict from `ccx vcs pr status`, hold
age, and whether the owner reviewed (`owner_reviewed_at`, or an approval or change request by `owner_login`). Comments
never count, since agents comment under the owner's login.
`order: stack` walks each stack from its trunk; `age` puts the oldest first. Action `reviewed` posts an owner record to main.

Reads: `ccn ledger row list`, `gh api graphql`, `ccx vcs pr status`.

Actions: `reviewed`.

## rulings

_What did the owner and root rule, and which lanes was each routed to?_

**Rulings.** The drive's rulings, newest first: durable cc-notes answers labelled `program:<program>` or scoped to `branch`, and any
answer whose short id is in `ids`, each with the option the owner picked; then root and owner decision, go and answer
records on cci since the drive started, each with the lanes it was routed to.

Reads: `ccn answer list`, `cci records`.

## slack-feed

_Who answered in each test thread, and how long after it opened?_

**Slack test threads.** Messages from each Slack thread permalink in `threads` through `cc-slack thread --url`, newest first: sender,
permalink and latency from the thread's opening message, never the message text. `bot` keeps messages whose sender
name contains it; `prefix` keeps messages that start with it.

Reads: `cc-slack thread --url`.

## stack-graph

_How do the open PRs stack, and which bottom prefix can land?_

**Stack.** The ledger's open PRs as stacks rooted at their trunk branches, drawn from base and branch fields; a Graphite
`graphite-base/<n>` base names no PR, so `parents` maps a PR number to its parent PR or trunk. Nodes are toned by the
`ccx vcs pr status` verdict and ledger holds; the largest landable bottom prefix of each stack is highlighted.

Reads: `ccn ledger row list`, `ccx vcs pr status`.

## tasks

_What is the root session working on right now?_

**Root tasks.** The root session's task list (the newest of `sessions` that has one), narrowed to `statuses`.

Reads: `the root session's task list`.

## timeseries

_How has this number moved over the window, against its thresholds?_

**Time series.** Lines from a Datadog `query` through pup, one per series, or from the `y` fields of every row in the files matching
`files`, plotted against `x`; `thresholds` draws labeled rules.

Reads: `pup metrics query`, `result files`.

## view

_Which rows of this table, file or record match the filter?_

**View.** The declarative engine: rows from another card's Table (`source`, a card id), the newest file matching `file`
(markdown tables, JSON, JSONL, CSV or TSV), or a cc-notes record (`ccn`); then `where` regexes (a leading ! negates),
`since` (30m, 48h, 7d), `match` named groups, `sort` (-field for descending), `latest_by`, and `limit`. `columns`
takes `key` or `key:kind`.

Reads: `another card`, `files`, `ccn`.

## release.builds

_Which release builds ran, and what did each one ship?_

**Release builds.** Release, hotfix, rollback, deploy, plan and check builds from the release pipeline, newest first, with the PR each ships.

Reads: `bk api`, `git log`.

## release.census

_Are more stacks reaching 0/0 over time?_

**Stacks at 0/0 over time.** The census count of stacks at 0/0 and its denominator, from cci state records carrying census fields over 48 hours.

Reads: `cci records`.

## release.incidents

_Which incidents are open, and which lanes work on them?_

**Incidents.** Incident threads from 72 hours of cci records, open first: their status, latest record and lanes.

Reads: `cci records`, `cci digest`.

## release.landed-per-hour

_How many PRs landed in each of the last 24 hours?_

**PRs landed per hour.** PRs whose landed record arrived in each of the last 24 hours.

Reads: `cci records`.

## release.lines

_Which PR and release records arrived since the drive started?_

**PR and release records.** GO, OPENED, CLAIM, READY, LANDED, RELEASE and FIX-LIVE records since the drive started, newest first.

Reads: `cci records`.

## release.stacks

_Which stacks can Platy deploy, and why not the rest?_

**Platy deployability.** Each census stack, grouped by release target: proven, unproven or blocked through Platy, its drift against trunk,
why it is not proven, and the lane working on it.

Reads: `bk api`, `git`, `cci digest`.

## release.tiles

_How is the release pipeline doing today?_

**Release overview.** Stacks at 0/0, releases today, the median passed release, PRs landed today against open, open incidents and lanes working.

Reads: `bk api`, `git`, `cci digest`, `cci lanes`.
