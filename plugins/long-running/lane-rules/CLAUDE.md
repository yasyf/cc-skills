# Lane rules

These are the rules from the owner's global instructions that a drive lane needs. A drive session below the top roots loads this file in place of `~/.claude/CLAUDE.md`. Your role's agent definition and brief come first; this file fills in what they leave out.

- **Judgment:** you own your deliverable. Decide the forks you meet, act, and name what you chose in your return; his later word steers it. Return to ask only for a limit below or a question that is truly his.
- **Tests:** never run tests locally. CI grades the work: push, read the CI log, fix and push again. You may run a build, a typecheck and a linter on what you touched.
- **Shipping:** ship through `ccx vcs ship --no-watch`, or the PR verb the repository's own skills name. The drive's watch follows each PR's CI from GitHub's webhooks, so a ship that waits on CI only holds the lane: a lane's environment sets `CCX_SHIP_NO_WATCH=1`, and the flag covers a ccx older than 0.96.25. A PR gets a written body and is never a draft. When ccx refuses, run the raw command marked `# ccx:raw` and report the refusal verbatim.
- **Held installs:** when a commit of yours replaces one an install hold names (`lane hold-install <sha>`), end its message with the footer `Lifts-Hold: <sha>`, so every tag carrying your commit lifts that hold; a plain `git revert` lifts it by its own "This reverts commit" line.
- **Paths:** new worktrees go under `~/repos/claude/worktrees/<repo>/<lane>`. Disposable scratch goes under `~/.vcache/scratch/<lane>`. Never use `/tmp`, `~/.cache`, or a new folder in `~`.
- **Python:** no background, bulk or dataset Python. Sample with zsh, and scan transcripts with `cc-transcript`.
- **Comments:** zero comments in code. The exceptions are public-API doc comments, TODOs, and workarounds the code can't express.
- **Outside impact:** before changing anything code outside the repository can observe (a builtin, an API or SDK call, a consistency level, a default, a schema, a wire or storage format), search each symbol the change touches with `gh search code '<symbol>' --owner Forge-FDE --extension sand`. Put what it finds in the PR body's impact section.
- **Read-only repositories:** customer and forward-deployed engineers' repositories, the `read_only_repos` the checkout's `.claude/long-running.toml` lists, are clone-and-read only. A change that belongs in one goes back to its owner as an ask with the patch attached, never a push; the lane's Bash hook refuses the push.
- **His Approve merges it:** a PR carrying his Approve merges, dangerous or not, with no wait for him to be present (his ruling at 2026-11-17T02:14:24Z: "get rid of this fucking presence bullshit if I approve something its approved"). Only the lanes the drive config's `premerge_lanes` names run its staging test before merge; everything else tests on staging after it merges (his ruling at 2026-11-17T01:00:34Z: "Im talking about the fucking ssql work nothing other than the ssql work needs to run before merging it can test on staging after merging").
- **Shell:** Bash runs zsh: write POSIX/zsh, never fish. No `sleep`, and no `until` or `while` loop polling a file, a process, `gh` or `orca orchestration check`, at any interval. To wait on a PR, build, card or his tap, end your turn with `lane end-turn` naming what it waits on; the drive's watch wakes the lane when that moves.
- **Transcripts:** read Claude session history only with `cc-transcript` (`list --project <substring>`, `grep`, `show`). Never use a recursive `grep`, `rg` or `find` over `~/.claude`.
- **Sessions:** never stop, signal or close another Claude or Codex session, Orca, or a terminal host.
- **Long calls:** messages reach you only between tool calls, so a foreground call past about 30 seconds leaves you deaf for its length. Run anything longer in the background and end your turn to wait.
- **Progress:** progress and state go to `lane log` and `lane next`, which his page shows; a lane posts to him only what he must read or decide. A block only he can clear, written on your lane by `lane block`, is told to him in his thread within minutes, saying what clears it: the supervisor wakes you for one you have not.
- **His decisions:** a decision only he can make is asked within a minute, as one card with 2 to 4 options and a recommendation. His ruling is applied as worded, never narrowed. Ask with `lane say "<question>" --options "<recommended>" --options "<other>"`, and before you ask, check his rulings your brief lists and the drive's shared rulings: build what one already decides, cite it, and ask only what none settles.
- **Lane calls:** each lane call is a message, so make each one right the first time and send it once. Progress goes to `lane log`, never to him; `lane next` writes the plan; each PR the lane ships is recorded with `lane pr add <repo#N> --words "<what it does>"`, and an ask of his you finished with `lane done <ts>`. Name any step no lane verb covers in your end-turn for the session that started you.
