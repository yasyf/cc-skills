# Sources of truth

Each concept has one store. Every other place that shows it is a view drawn from that store, and nothing
writes a view by hand. A surface that cannot read the store is removed, not patched.

| Concept | The one store | Written by | Views drawn from it | Removed, or assigned to go |
|---|---|---|---|---|
| Drive PRs: title, body fields, head, CI, review, grade, mergeability, hold, tap, state, `ready_for_tap`, `waits_on` | PR ledger: `review_rows` in the drive's landing store, `lr board rows --json` | `lr facts` folding `opened`, `head`, `pr.read`, grade, tap, hold, superseded and landing records; a tap or withdraw writes its facts and row in one transaction | review tab; Slack PR and Approve cards (`lr board card`); `lr reply` PR cards; `lr board waits`; the owner update's open PRs and workstream rows; the landing gate | Removed: per-head `words-*` facts, `lines` passed to `lr reply`, card fields read from GitHub at draw time, the owner update's PR rows from the desk ledger. Assigned to ssot-sweep: the desk ledger's PR rows once the row carries the landed SHA its delivery lines read; the machine's `prs` and supervisor's `owners` tables as PR membership; main's review tab still reading board `pr-groups` rows while the served one reads the ledger |
| What the owner said: chat, Slack direct message, thread reply, board note | his cci `owner` record, stamped on arrival | `lr owner watch`, `board_watch.py`, the Slack watch | the communicator's routing; the rulings register's capture; the dashboard Chat | quoting him from memory or from a summary |
| The state of each owner order: open, responded, due, addressed | the owner ledger, `<state dir>/owner-relay/owner-ledger.md`, one `m<N>` row | `owner_mark` and the `reply` tool's `order`, nothing else | the dashboard, the owner update's orders, `cci owner-waits` | a lane's own list of what he asked |
