# Design first

Before any builder starts on a part, the coordinator decides whether the part carries a tricky design: a choice between two reasonable shapes that are costly to switch between once built, so he decides the shape before a PR goes up. It counts when the part settles a data layout or file format (such as where a journal keeps its index), a schema or migration shape, a lock, queue, scheduler or other coordination, a public or Sand-facing API shape, or a new background process. When unsure, it counts.

1. **One design lane, first.** The part's first job is a read-only `fable` design job that produces no code and no PR, fleshing out the design with worked examples before any question goes to him. Add it with `drive job add design --order <o> --part "<part>" --goal "<one line>"`, then start it with the Agent tool: `subagent_type` `long-running:designer`, `model` `fable`, `effort` `medium`, `run_in_background: true`, a short `description`, no `name`, and the brief from [Jobs](jobs.md) as `prompt` (ending with `Drive:`, with no `Serves`, `Done when` or `Handoff` line, and a `Plan:` naming the files, PRs and findings it starts from); the `agent_brief` hook denies an Agent call that passes `name` or puts any agent but `long-running:designer` on `fable`. Its return opens `DESIGN <part>` and gives the design in plain words with a worked example of each piece, such as imperative beside declarative API calls, schema rows or file bytes. It names what his words already settle and keeps each real fork with `drive job ask` as an `ASK` block: the design in one line, a Show me of each option in code or a fitting visual, and two to four one-line options, recommendation first. Every option lands releasable alone by [Land a change](landing.md#every-pr), split until each part is safe without a follow-up backfill or hand-run command; `drive job ask` refuses a question his recorded answers settle, an out-of-shape card or a land-now-fix-later option.
2. **He is asked before any PR.** Each fork goes to him as its own question card from the `DESIGN` row of the job results, with the fleshed-out design and Show me above the options rather than a wall of findings or a high-level summary. Meanwhile, a builder may build the recommended option of each fork on a pushed branch.
3. **Built is a state, not a PR.** That builder opens no PR and returns `BUILT <branch>, waits on <cards>`. The coordinator records it with `drive job set <j> --state built --branch <branch> --waits <card>`, passing `--waits` for each card's waits id or Slack link so the ledger, `drive status`, `drive view`, the dashboard and his status tab show the built branch and its cards; `drive job set` without both flags and `drive pr add` while a card is open refuse. The watch drops each card as he answers it and emits `FREE <j>` once the last card and any question from the job itself are answered. A handoff builder then opens the PR, rebuilding first where his pick differs from the recommended option.
4. **Nothing lands around an open card.** Record an open design card on an existing PR with `drive pr set <url> --waits <card>`, which withdraws any open Approve card; `drive pr set --tap` and `drive card` refuse while a card holds. The watch emits `FREE <pr>` once the last card is answered, without closing the PR. Never land, enqueue or settle a change on a recommended option while its card is open: if he orders the change landed first, redraw that card in his order's thread and land after he answers. His question queue orders cards by how many green approved PRs and built branches they block, naming the blocked features on each card and the blocking cards on each feature.
5. **The builder carries the design.** Set the builder brief's `Plan:` to the design and `Decisions that bind` to his verbatim answers. A builder that hits a new fork mid-build stops and returns `ASK` with it instead of choosing.
6. **No card for a design he never saw.** Return a `READY` PR that makes an unanswered design choice as a design question; `drive pr set --tap` refuses without `--design asked:<his answer id or card permalink>` or `--design none`.
