# The drive verbs

Every verb `drive` takes and every flag of each, one row per verb, as the installed CLI parses
them; a test holds this table and the parser equal. Read a verb's row with
`drive manual verbs "<verb>"`, such as `drive manual verbs "job set"`, never with
`drive … --help`. The rows leave out `--drive <name>`, which defaults to this session's drive,
and `--json`, which prints JSON. `[ ]` marks what may be left out, and `...` what repeats.

A session runs the verbs it uses each turn as the drive MCP server's tools, never through Bash:
`heard` and `status` take the verb's flags as fields, and `order`, `job` and `pr` take `ops`, a list
run in order that stops at the first refusal, each op one verb (`order`: add, set, posted; `job`:
add, set, brief; `pr`: add, set) with its flags as fields, dashes as underscores, its
positionals by the names below, and an op after an add that names no `id` acting on what that add
made. `drive job set j3 --branch lr-watch --said "pushed"` is
`job(ops=[{set: {id: "j3", branch: "lr-watch", said: "pushed"}}])`. A job add's `order` may be
the fields of an order add, which adds that order first. `record` posts records to the other
session. Every tool takes `dry_run`, which prints each command or record and runs nothing, and
prints one line for each op. A verb that runs for minutes, such as `drive job launch`, `drive job
resume` or `drive job end`, stays a background Bash call, since a tool call ends at three minutes.

| Verb | Takes |
|---|---|
| `drive start <name>` | `--role communicator/coordinator`, required; `--channel <his DM id>`; `--watch <channel>`..., another channel the coordinator subscribes to |
| `drive order add "<his words>"` | `--from slack:<channel>/<ts>`, default terminal; `--thread <ts>`, refused unless Slack reads it as a thread in his DM, or in the channel of the message `--from` names when it is that message's thread, and refused naming the thread a reply's ts is in; `--due <time>` his ack promised a line by; `--kind answer/build`: an answer is one reader that researches and answers, a build gets an Opus reader's `Researched:` block before its builder or designer, whose briefs name that reader; `--complex`, more than a one-fact lookup, so its lanes run on Opus; `--parts "<part>"...`, each deliverable his words name; `--incident`, a build, which needs a `fix` part and records a codex job on each part, its agent started at once; `--joins <o>`, an incident on the failing service of open incident `<o>`, with its record and no job; `--project <name>` and `--workstream <name>`, both required, the Now screen files it under |
| `drive order set <o>` | `--state open/working/waiting/done/dropped`; `--due <time>`; `--note "<text>"`; `--proof <link>`; `--thread <ts>`, checked as `drive order add` checks it; `--lined`; `--withdrawn <link>`, his message calling off a promised time; `--parts "<part>"...`, replacing the list; `--incident`, refused until a job owns its `fix` part, or `--no-incident`; `--kind answer/build`; `--complex` or `--no-complex`; `--project <name>` and `--workstream <name>`, each empty to take it out, which alone leaves the order's time; `--record <seq>`, the handler's report a close from the communicator needs |
| `drive order unfiled` | each open order naming no project or workstream yet, then the pairs in use |
| `drive order posted <o> [<link>]` | the drive's post in Slack; `--record <seq>`, the report it carries, delivers the part its `part` attr names or each part its `job` attr's job delivers, in any channel; `--part "<part>"`, the part a post delivers, or with `--undo` the part whose mark it takes back |
| `drive job add <kind>` | `<kind>` builder, reader, design or codex; `--order <o>` and `--goal "<one line>"`, required; `--agent <id>`; `--repo <owner/name>`; `--branch <b>`; `--worktree <path>`; `--remote`, a builder on a Sprite; `--part "<part>"`..., of its order, default its only part. Prints the job id. Refuses anything but a reader on an answer order, and a builder or designer on a build order before its reader kept the `Researched:` block |
| `drive job set <j>` | `--state stopped`, a job that ends unfinished, the one state set by hand; `running`, `waiting`, `built`, `done` and `failed` come from the line the job returns, which the watch reads or `drive job report <j> -` takes, so the verb refuses each with the return words that set it; a state the job already holds changes nothing and says so; `--said "<its line>"`; `--agent <id>`; `--branch <b>`; `--pr <url>`...; `--repro <file>`; `--part "<part>"`..., of its own order or of the one `--carries <o>` names, another order it delivers for; `--card <link>`, a question card it asked on, kept beside its others, each carrying its parts until he answers it; `--waits <card>`..., a card of his by its Slack link or waits id, never a job, so his tap frees it; `--no-waits`, dropping every wait first; `--told <link>`, the drive's line in an incident's thread linking the card, which a job on an open incident order needs before it takes a card |
| `drive job ask <j> [<file>]` | keeps the question beside the job's other open ones, once checked against his answers in cc-notes from the coordinator's checkout, whatever directory it runs in; the ASK block's file, `-` for stdin, default a remote lane's latest report; `--unsettled "<why>"`: each answer of his the refusal listed, by id, and why it does not settle this, his words under a card of the job among them; refuses a block whose `Findings:` carry no `Direct fix:` line naming the option its diagnosis points at, or `none: <why>`, and one recommending another option when the summary never names the direct fix and says why |
| `drive job card <file>` | the card a kept ASK block draws, as JSON, and gives the question kept in that file its waits id; `--waits <drive>:<j>-<seq>`, required, where one naming no job of the drive only draws the card; `--reworking "<what is being redone, and when it is back>"`, one line atop the body saying the question is being redone and why, its words and buttons kept; a block kept under older rules redraws as kept, a fence of words as a code block and markdown in its question or options as the words it marks; refuses to redraw a card his words under it answered with another question |
| `drive cards redraw` | each of his open question cards whose ASK file a job's question keeps, as the JSON `drive job card` prints, one line each in one pass, for `say(card=…)`; `--waits <drive>:<j>-<seq>`..., only those cards; names each card it could not redraw after the rest and exits 2 |
| `drive job report <j> [-]` | `-` keeps the return piped on stdin, its first line setting a running job's state and said line, and refuses a reader's `DESIGN` without two to four options and a build's `READY` without a `REUSES:` line when its research found what exists; with nothing, prints the kept one |
| `drive job brief <j>` | writes the job's brief from his order's stored words, each ruling's recorded words whole, the earlier jobs' transcripts and, for a build order's builder or designer, `Researched: <its reader's job>` from the order's research, and prints `Read your brief first: <path>`, a local job's whole Agent prompt; `--serves "<port of #N, drive tooling or his order>"`, `--done-when "<check>"` and `--where "<repo, base, branch>"`, required; `--ruling <answer id>`...; `--runs-as "<service account>"`; `--handoff "<event>"`; `--plan "<section>"`; `--incident "<line>"`; `--scratch <dir>`, default one in the drive |
| `drive job launch <j> [<brief>]` | starts a remote job's lane on a Sprite from the brief `drive job brief` wrote, or this file; `-` reads it from stdin; `--local` starts it as an Orca worker on this Mac instead, read through its Dispatch like a Sprite lane; refuses a build order's builder or designer brief with no `Researched: <its reader's job>` line |
| `drive job resume <j> "<text>"` | answers a remote lane or sends its next event; `-` reads the text from stdin; run it with the Bash timeout at 20 seconds (`timeout: 20000`), never `run_in_background`, since a send returns in about 5 seconds and a relaunch moves itself to the background at 20 |
| `drive job replies <j>` | each result and question a remote lane sent, oldest first |
| `drive job end <j>` | ends a done remote lane and frees its Sprite |
| `drive pr add <url>` | `--job <j>`, required; `--tap`, waits on his tap |
| `drive pr set <url>` | `--tap`, which needs `--serves <o>` and `--design asked:<answer>` or `none`; `--no-tap`, withdrawing his card, which needs `--why "<reason>"`; one of `--exempt "pure port"/test-only/ci-only/"flake fix"/"incident fix"`, `--no-exempt` or `--port-of <N>`; `"incident fix"` is refused to a PR whose title or body says it reverts a change, naming the tap card it waits on instead; `--fundamental "<what changed>"`, clearing his tap and any exemption; `--tapped Approve/Hold`, a tap he gave elsewhere, and `--tap-source <where>`; `--waits <card or job>`..., refusing a card on a PR of an open incident order, which lands on the recommended option; `--no-waits` |
| `drive pr tapped <url>` | whether his tap lets it land: exit 0 if so, 1 if not |
| `drive place` | where the next monorepo builder starts |
| `drive bound <run> <command>...` | runs the command after `--` with a lane's Run bound to this terminal |
| `drive answer [<id>]` | `--title "<the question>"`, `--words "<his words>"` and `--link <permalink>` on the first call, with `--label <label>` for each cc-notes label beyond `scope:durable` and `drive:<drive>`, which records his answer in cc-notes from the coordinator's checkout, whatever directory it runs in, prints its id, lists every open card and PR and exits 2; an id in place of `--title` names one already recorded; then `--stands <key>...`, `--superseded <key>=stop` or `<key>=<j>`..., `--reopened <key>=<j>`... and `--others-stand` until each is marked |
| `drive heard` | `--away`, he said he is going to sleep or away |
| `drive status [<id>...]` | the orders these orders, jobs or PRs belong to, open or closed, each whole: its words, parts, and each job's goal and said line; default every open order, a line each, under the sessions; each PR line carries its title, quoted, beside its number |
| `drive manual <page> [<row>]` | `<page>` start, records, communicator, coordinator, jobs, scope, design, messages, concepts, landing, incidents, migration or verbs; `<row>` prints the table rows whose first cell names it |
| `drive context` | `--role communicator/coordinator`, default this session's |
| `drive view` | what waits on him and where each feature stands |
| `drive dashboard` | `--port <n>`; `--serve`, in the foreground |
| `drive watch` | starts the drive's watch as its own process unless one runs, and in the coordinator's session points its cci channel at the watch's records; `--loop` runs the watch in the foreground, as the process it starts does |
| `drive card` | answers one cc-slack card request, JSON on stdin and stdout |
| `drive mcp` | serves `say` and the verb tools to a Claude Code session over stdio, as this plugin's `drive` MCP server, listing the newest install's tools and telling the session when an install changes them; `--list` prints the tools as JSON |
| `drive tool <name>` | `<name>` say, heard, record, order, job, pr or status; runs that MCP tool on the JSON arguments read from stdin and prints its lines |
| `drive install <plugin>@<marketplace>` | `--sha <merge sha>`; `--repo <owner/name>`; `--timeout <seconds>`, default 900 |
| `drive setup` | `--bin-dir <dir>` for the `drive` shim |
