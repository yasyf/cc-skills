# The drive verbs

Every verb `drive` takes and every flag of each, one row per verb. A test keeps the table equal to
the parser. `drive manual verbs "<verb>"` prints one row. Rows leave out `--drive <name>` (default
`$CLAUDE_LONG_RUNNING_DRIVE`, which every process the drive starts carries, else this session's
drive) and `--json`. `[ ]` marks what may be left out, `...` what repeats. `drive status <id>` reads
an order, job or PR, and `drive order show` and `drive job show` print the same. A verb names a PR as
`owner/repo#N` in any case, its URL, `#N` or its bare number. A bare number two tracked PRs share is
refused, naming each. A PR the drive does not track is named as `owner/repo#N` or its URL.

How verbs run:

- Any install's verb, MCP call or hook reads and saves the drive whatever install saved it last. A
  `drive` from an older install hands itself to the newest before it acts, and `drive --root` prints
  the folder of the install it runs, where a proof file finds `hooks/` and `lib/`.
- A write waits up to five minutes for the drive's lock, then refuses and changes nothing, naming
  the process that holds it.
- A launch, resume or end the watch ran that refused says why in the watch's
  `EVENT relaunch_refused …` line and in the drive's `relaunches.log`.
- A Sprite lane's `drive` sends each verb to this Mac as one Orca question, `DRIVE <its words>`,
  with stdin and each file a word names. The watch runs it here and the lane's `drive` prints its
  output and exits with its status. A lane may run `job report`, `job ask`, `job set --repro`,
  `job replies`, `job held`, `pr add`, `pr set --flaky`, `plan search`, `datadog`, `fde-scan`,
  `manual`, `page-owner` and `status`: reads on any job of its drive, writes on its own job alone. A
  picture a card or PR shows by a path on the Sprite is copied into the job's scratch folder first,
  so the card drawn here opens it. `break-glass` is refused there, since its command would run on
  this Mac as its user.

## Tool or Bash

- A verb with a tool on the drive MCP server runs there or in Bash. One tool call carries every op
  the turn needs. Other verbs run in Bash.
- `heard`, `status`, `search_plan` (which runs `drive plan search`) and `page` (which runs `drive page make`) take the verb's flags as
  fields. `record` posts records to the other sessions. `order` (add, set, posted, told), `job`
  (add, set, brief), `pr` (add, set) and `incident` (open, stop, freeze) take `ops`, a list.
- Each op is one verb, its flags and positionals as its schema's fields, dashes as underscores:
  `drive job set j3 --branch lr-watch --said "pushed"` is
  `job(ops=[{set: {id: "j3", branch: "lr-watch", said: "pushed"}}])`. An op after an add that names
  no `id` acts on what that add made. A job add's `order` may hold an order add's fields, adding
  that order first.
- The whole list is checked before any op runs. One refused op runs none and prints every refused
  op with its fix. Then the ops run in order, a line each. `order`, `job` and `pr` save the drive
  once for the call, merged into the drive as it stands then; a call that changed a field another
  write changed meanwhile is refused and keeps nothing. `incident` keeps each op before a refusal
  and names the ops left unrun.
- From Bash, several ops go as one `drive tool <tool>` call with `{"ops": [...]}` on stdin, which is
  one write where a chain of `drive order add` calls is one each.
- Every tool takes `dry_run`: each op runs its verb's checks, prints each command or record and
  keeps nothing. An op that reaches a command doing more than read, such as a Slack post, stops
  there and names it.
- A tool call ends at three minutes, so `drive job launch` and `drive job end` run as background
  Bash calls.

| `drive start <name>` | Binds this session to a role of the drive. `--role communicator/coordinator/meta`, required. While no meta session is bound it also opens one under cci in an Orca terminal of its own, printing its terminal or why it did not start. `--watch <channel>`..., another channel the coordinator subscribes to. `--project <name>`, with `--role coordinator`, binds this session as the sub-coordinator of a project an order is filed under, replacing any bound for it, and loads the watch, which runs that project's passes; its context names the project, its cci lane (the name lowercased, each run of other characters a dash) and its cursor `coordinator-<lane>`. `meta` and `communicator` take no `--project`. Refuses a project no order is filed under, naming those in use, a session that holds another role, a lane name already taken or ending in `-<digits>`, and a session outside an Orca terminal and tmux, naming the `cci session register` and `orca terminal create` lines that start it there |
| `drive move <role>` | `<role>` communicator, coordinator or meta. `--his-word <permalink>`, his message naming the move, required. | `drive order add "<his words>"` | Adds an order and prints its id. `--title "<a few words>"`, required: the name the dashboard shows, at most 60 characters, no link. `--project <name>` and `--workstream <name>` file it on the dashboard's Now screen: both needed on his order, default `The drive` and `Drive tooling` on a `Drive tooling:` order; His order joins another only by `--joins`; stderr names the likely one. Prints each open question card its words point at |

`--no-priority` hands it back to its project's coordinator. `--every <minutes>`, 0 taking it out. `--project <name>`, `--workstream <name>` and `--title "<a few words>"` refile or rename it, the first two empty to take them out. `--unjoin` takes it off the order it joined: that feature's jobs carry it no more, it files under its own project and workstream, its own reader starts with `drive job add reader`, and the print names each job whose worker already took its words. `--rework <PR>=<his permalink>`..., as `drive order add` takes it. `--record <seq>`, the report a close by the communicator names; `--state dropped` with `--note` needs none. `--fresh` or `--no-fresh`, as `drive order add` reads them. `--dry-run` runs every check, keeps nothing and prints each field it would change. The session holding the order changes its parts, kind, standing, options and incident marks; the communicator may file his words onto any order's parts and kind |

| `drive transcripts-keep <j>` | `<j>` a job whose lane runs on a Sprite. Copies the Claude Code transcripts that Sprite holds now to the drive's `jobs/<j>.<dispatch>.transcripts/` through the Sprites file API, reading only files that changed. The watch runs it at each turn end of a Sprite lane, logging to the drive's `transcripts.log`, so a relaunch after that Sprite is lost resumes the lane's session from a copy no older than its last turn |
| `drive disks-check` | No arguments. Reads `/sys/fs/ext4/nbd0/errors_count` and `/sys/block/nbd0/stat` on each Sprite lane through the Sprites file API, which answers while a wedged disk stalls ssh. A Sprite whose ext4 counted errors, or whose in-flight requests stood unchanged since the last check, is checkpoint-restored at once, and its lane's death is recorded as restored, so the next lane resumes its Claude session on that Sprite. The watch runs it every two minutes, logging to `disks.log` |
| `drive mcp` | Serves `say` and the verb tools over stdio as this plugin's `drive` MCP server, one per session. Each call runs the newest installed drive, forked from that install's warm `--warm` process, and is killed on a cancel or after 180 seconds, its reply keeping what it printed by then; the server's own code changes at the session's next start. `--list` prints the tools as JSON |
| `drive tool <name>` | `<name>` say, heard, record, order, job, pr, incident, status, search_plan or page. Runs that MCP tool on the JSON arguments read from stdin and prints its lines; `-h` prints the tool's description and each JSON field with its type, whether it is required and its description, and runs nothing |
| `drive install <plugin>@<marketplace>` | Installs a plugin's newest release on this Mac and reloads the drive's sessions onto it. `--sha <merge sha>`, the merge the release must hold; `--repo <owner/name>`; `--timeout <seconds>`, default 900. A git command that could not reach GitHub runs again within 20 seconds until the timeout. With `--sha`, when no release will hold the merge, it prints `no release: <why>`, installs nothing and exits 0. It first installs each sibling the release's `plugin.json` floors name that runs an older release, and holds for his Install now tap when Captain Hook.app is below a captain-hook floor. For cc-context, cc-inbox, cc-notes, cc-orchestrate, cc-present, cc-review, cc-slack and codex it fast-forwards the `yasyf/tap` clone and runs `brew upgrade yasyf/tap/<binary>`. For long-running it runs the new install's `drive migrate`. Then it reloads each session as `drive reload` does, skipping one already reloaded since the install. It proves nothing; the watch's `drive job prove` does |
| `drive reload` | Types `/reload-plugins` into every session of the drive, the communicator, the top coordinator and each sub-coordinator, and prints a line per session. Each goes to one process per Orca terminal, `drive reload --seat <seat>`, which waits until the session reads idle, types it once, holds the terminal until the transcript shows its `Reloaded:` line, and logs to the drive's `reloads.log`; a session no terminal runs is skipped with a line. `--seat <seat>` is that process. `--force`, with `--seat`, types it even into a session already on the newest install, and `--terminal <handle>` names the Orca terminal the install already found. A session running outside the drive's checkout is registered with cci there and typed `/exit` once idle, so cci resumes it in the checkout |
| `drive advised <command>...` | `--drive <d>` and `--lane <l>`, both required. Execs a root session's claude command, its model and advisor flags included, as its Start or resume line runs it. When Claude Code refuses the advisor it drops the advisor flag and starts without it, saying so in the terminal and to `meta@<d>` as one `defect` record a day per seat |
| `drive migrate` | Makes each one-time change to a drive's files that an older install still owes, to every drive on this Mac, each once. `drive install` runs it from the new long-running install before any session reloads onto it, and `drive start` on the drive it makes |
| `drive setup` | `--bin-dir <dir>` for the `drive` shim |
